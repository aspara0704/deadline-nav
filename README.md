# Deadline Navi v0.5.1

到着期限を守りつつ、追加で支払う高速料金を最小化するためのWebプロトタイプです。

## v0.5.1 の追加機能

- 走行中のGPS継続取得
- 通常時は約3分または5km移動ごとに自動再計算
- 高速切替期限が30分以内、または下道余裕が30分以内になると、約1分または1.5km移動ごとに再計算
- 推奨高速入口が変わったときだけ音声通知
- 「高速不要 → 高速が必要」「高速が必要 → 高速不要」「期限達成困難」への状態変化も音声通知
- iPhoneのホーム画面へ追加しやすいWeb App manifestを追加
- 画面Wake Lockにブラウザが対応していれば、自動監視中は画面スリープを抑制

## v0.4.6 から継続している中核ロジック

1. Google Routesで下道優先ルートと通常ルートを取得
2. 下道だけで実質期限内なら、追加料金0円を最適解として即終了
3. 高速が必要な場合、下道ルート上の仮想地点を将来時刻込みで評価
4. 到着期限の境界周辺だけNAVITIMEの乗降IC検索で実在ICを取得
5. 実在IC群をGoogleで粗密探索し、期限直前の候補を必ず正確評価
6. 期限内候補のETC料金をNAVITIMEで比較し、最安入口を推奨

## 自動監視の前提

v0.5.1の自動監視は、2台目のiPhone等でSafariを前面表示したまま使うことを想定しています。iOSのブラウザをバックグラウンドに回した場合の継続実行は保証しません。

「音声テスト」を一度押して、端末から日本語音声が出ることを確認してから走行してください。

## 配布する場合の最短構成

GitHub Pages等のHTTPS静的ホスティングへ、このフォルダの中身をそのまま公開します。APIキーはリポジトリへ書き込まず、各端末で画面から入力します。

### GitHub Pages の例

1. GitHubで新しいリポジトリを作成
2. このフォルダ内の `index.html`, `app.js`, `styles.css`, `manifest.webmanifest`, PNGアイコンをリポジトリ直下へアップロード
3. リポジトリの Settings → Pages で `main` ブランチの `/ (root)` を公開元に指定
4. 発行された `https://<username>.github.io/<repository>/` をiPhoneで開く
5. Safariの共有メニューから「ホーム画面に追加」
6. Google APIキーは公開URLをHTTP referrer制限に追加し、Maps JavaScript API / Routes APIだけにAPI制限する
7. NAVITIMEのX-RapidAPI-Keyはソースに埋め込まず、信頼する端末ごとに手入力する

## セキュリティ

- Google Maps JavaScript APIのブラウザキーは、公開先HTTPSドメインにHTTP referrer制限を設定してください。
- RapidAPIキーはブラウザからNAVITIMEへ直接送るため、端末の所有者には見えます。少人数の信頼できる試験利用なら手入力方式で運用できますが、不特定多数に配布する場合はサーバー側プロキシへ移すべきです。
- GitHub Pages自体は公開サイトです。APIキーをHTML/JavaScriptへ直接埋め込まないでください。

## 実走前チェック

- Google APIキー設定済み
- NAVITIME RapidAPIキー設定済み
- iPhoneで位置情報を許可
- 音声テスト成功
- 目的地・到着希望日時・安全マージンを確認
- 「自動監視を開始」を押す
- Yahooカーナビ等は別端末で通常どおり使用

## 注意

本プロトタイプは運転判断を補助するための試作品です。高速入口や道路規制、事故、通行止め等は実際の道路標識および通常のカーナビでも確認してください。運転者本人が走行中に画面操作をしないでください。

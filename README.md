# Deadline Navi v0.7.1

「間に合うなら、まだ下道で。」

到着期限を守りながら、高速道路へ切り替えるタイミングを判断する iPhone 向け PWA プロトタイプです。

## v0.7.1 の重点

### 1. NAVITIME を必須依存から外しました

- NAVITIME / RapidAPI キーは任意です。
- 月間上限などで NAVITIME が HTTP 429 を返した場合、その月は補助 API を自動停止し、同じ失敗リクエストを繰り返しません。
- IC探索は、保存済み候補 → 小範囲の OpenStreetMap 探索 → 必要時のみ NAVITIME、の順で行います。
- 京都〜東海方面については、外部のIC検索が失敗したときだけ使う内蔵候補名も持たせています。
- 一度取得したIC位置は端末内へ保存し、以後の探索で再利用します。

### 2. Google の料金情報を「取れる前提」にしません

標準 Routes API には `JP_ETC` と料金計算機能がありますが、実際の日本の経路で必ず金額が返るとは仮定しません。

- まず料金を要求せず、交通を考慮した到着時刻だけで候補を絞ります。
- 最終候補（最大4件）だけ Google に料金を問い合わせます。
- Google が金額を返さない場合だけ、NAVITIME が利用可能なら最大2件を補完します。
- どちらからも料金を取得できない場合でも、到着可能な高速入口の案内は継続します。「0円」と誤認せず「料金未取得」と表示します。
- 取得済み料金は短時間キャッシュし、同じ料金を何度も問い合わせません。

### 3. 「間に合うICが消える」問題への対策

- 下道ルート周辺だけでなく、Google推奨ルート側も候補探索に使います。
- 前回の推奨ICを次回計算でも保持して再評価します。
- Google推奨ルートが期限内なのに安全なICが見つからない場合、探索失敗を「全ICが間に合わない」と誤表示しません。
- 京都〜東海方面では、巨椋池ICなど横方向・少し戻る高速入口も最終フォールバック候補に含めます。

### 4. 走行中の画面を動かさない

- 自動再計算では、現在の推奨カードを消してから描き直す処理を廃止しました。
- 計算中・一時エラーでも現在表示を維持します。
- 自動更新の通信エラーを大きなエラーバナーとして差し込まず、走行中モニター内で静かに通知します。
- 主要カードに安定した高さを持たせ、数値更新によるレイアウト移動を抑えています。
- 自動更新では `scrollIntoView()` を行いません。

### 5. 音声案内

- 「音声案内を開始 / 終了」というユーザー向け表現に統一。
- 開始ボタンのタップ中に SpeechSynthesis を初期化します。
- 定期アナウンスは 1〜60分を1分刻みで設定できます。
- 重要な状態変化は定期間隔と別に通知します。

## 自動再計算

- 通常: 5分 または 5km
- 判断時刻まで30分以内: 3分 または 3km
- 判断時刻まで5分以内: 1分 または 1km

GPS自体は `watchPosition()` で継続取得します。GPS更新、経路再計算、音声案内は別々に制御します。

## APIキー

- Google Maps API キー: 必須
- NAVITIME / RapidAPI キー: 任意（料金・IC探索の補助）

APIキーを公開リポジトリへ直接書き込まないでください。

## データ

IC探索の一部に OpenStreetMap データを利用します: © OpenStreetMap contributors (ODbL)。

将来的には、国土交通省「国土数値情報 高速道路時系列データ」の最新現況データから全国ICカタログをビルド時に生成し、走行中のIC発見API依存をさらに減らす方針です。

# Deadline Navi v0.7.5

「間に合うなら、まだ下道で。」

v0.7.5 は、v0.7.4 の候補上限・同一計算内の再評価廃止を維持しつつ、**走行中は現在の推奨ICだけをまず軽量確認し、有効なら全国候補のフル探索を省略する版**です。

## 同梱ICカタログ

- `ic-data.min.json` は生成済みの2,085件をリポジトリ・配布ZIPに同梱します。初回起動時の外部データ生成は不要です。
- アプリは同じ配信元の静的ファイルだけを読みます。GitHub/raw/Overpass/NAVITIMEへの外部IC検索は行いません。GitHub Pages自体を配信元にする場合の静的アセット通信はあります。
- 全国カタログは元データの収録範囲に依存します。「同梱」は現存する全IC・全方向の完全網羅を意味しません。
- JCT併設ICは元データで名称にICを含むものを抽出します。JCT単独の地点は追加しません。
- 元データにない巨椋池ICは、出典付きの `tools/ic-supplement.json` で補完します。座標はIC代表点で、入口ランプの誘導点としての保証はありません。
- 起動処理と候補探索は同じ読み込み処理を共有し、旧版キャッシュがあっても同梱データの確認を待ちます。
- 読み込み・検証失敗時だけ旧版キャッシュへ退避します。キャッシュ利用と同梱利用は診断で区別します。どちらも利用できなければ内蔵候補のみで継続し、失敗を表示します。
- NAVITIME料金取得の補助は従来どおりです。IC検索のゼロ件条件とは区別します。

## 検証と配布

Node.js 22とPython 3で実行します。追加パッケージは不要です。

```sh
node --check app.js
node --test tests/local-ic.test.cjs
python tools/package-release.py
```

ZIPは `dist/deadline-nav-v0.7.5.zip` に生成されます。既知ICの存在、同梱読み込み、旧キャッシュからの切替、異常データ、外部IC検索遮断を検証し、必要ファイル不足なら生成を止めます。APIキーも有料API呼び出しも不要です。

PRの `Verify local IC release` が同じ検証を実行し、ZIPをActions artifactとして保存します。マージ・公開は別操作です。

手動確認は `DEPLOY.md` を参照してください。テストはGoogleの実経路品質やSafariでの動作を保証しません。

## データ更新（開発時のみ）

`Build bundled IC catalog` は固定リビジョンの元データを取得し、補完データを含めて生成・検証します。これは開発時の更新処理であり、利用者の起動時や走行中には実行しません。

```sh
python tools/build-ic-data.py /path/to/N06_Joint_fixed.geojson ic-data.min.json
node --test tests/local-ic.test.cjs
```

出典は `IC-DATA-NOTICE.md` を参照してください。

## v0.7.3 Matrix候補削減

- 通常探索は Matrix 送信前に最大12 ICへ絞ります。
- Google推奨ルート側の回復探索は最大18 IC、最終builtin fallbackは最大8 ICです。
- 合成チェックポイント9要素、通常12×2、回復18×2、fallback 8×2、ナビ変更目安最大6要素を合わせ、1計算のRoute Matrixを99要素以下に抑えるガードを入れています。
- 開発・診断に「発見 → Matrix送信 → 概算safe → 精査safe」を表示します。
- 同一ICの再評価抑止はv0.7.4へ残しています。


## v0.7.4 同一計算内の再評価廃止

- IC名を正規化したキーで、その計算中にMatrixへ送った候補を記録します。
- 通常探索で送信済みの候補は、回復探索では除外してから新規候補を選びます。
- 回復探索で送信済みの候補も、最終fallbackでは再送しません。
- 各段階の候補上限は v0.7.3 と同じ（通常12 / 回復18 / 最終8）です。
- したがって候補Matrixの理論上限は (12 + 18 + 8) × 2 = 76 elements。合成チェックポイント9要素とナビ変更目安最大6要素を加えても最大91 elementsで、99要素ガード内です。
- 診断には「評価済除外」と「Matrix新規」を表示し、再送が起きていないことを実機で確認できます。


## v0.7.5 走行中の軽量更新

- 音声案内中の自動更新で、前回の推奨ICがある場合はそのICだけを先に確認します。
- 現在地→推奨ICを下道条件で1回、推奨IC→目的地を交通考慮で1回確認します。
- 推奨ICが到着条件を満たす間は、全国IC候補探索・Route Matrix・料金再取得を省略します。
- 推奨ICが条件外、経路なし、または軽量確認エラーの場合だけ、従来のフル探索へフォールバックします。
- 開発・診断に「走行中更新」を表示します。軽量更新成功時の目標は Routes Pro 2 req / Route Matrix 0 elements です。
- 開発・診断の「走行中の軽量更新をテスト」で、実際に走行・5分待機しなくても同じ軽量経路を1回実行できます。
